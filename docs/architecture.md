# MVP 설계와 구현 경계

사용자가 첨부한 `threads_trend_automation_plan.md`를 요구사항 자료로 삼았습니다.
문서의 운영·외부 서비스 제안은 향후 구현 방향이며, 이번 초기 구조의 외부 작업 실행 지시로 취급하지 않았습니다.

## 흐름

```text
CLI / 향후 일일 스케줄러
  → TrendSource.discover(at)
  → PostSource.search(trends, at)
  → 게시물 ID 기준 최신 관측 선택
  → 인기 / 시간 보정 순위 + 텍스트 특징
  → SQLite + JSON / CSV
```

현재 어댑터는 두 개 모두 합성 데이터 전용입니다. 원문은 가상 게시물만 저장합니다.
실제 어댑터를 붙이기 전에 원문·작성자 보관의 허용 범위와 삭제·보유 기간을 구현해야 합니다.
누락 필드는 값을 추측하지 않고 사유와 함께 표현합니다.

## 저장 모델

| 테이블 | 키와 역할 |
| --- | --- |
| posts | 게시물 ID, 최신 게시물 메타데이터·본문 |
| metrics | 게시물 ID + 관측 시각, 누적 반응 스냅샷·누락 사유 |
| features | 게시물 ID + 관측 시각, 단순 텍스트·미디어 특징 |
| trends | 보고서 날짜 + 검색어 + 출처 |
| daily_rankings | 보고서 날짜 + 종류 + 순위, 게시물·관측 시각·실행 ID |
| job_runs | 모든 실행 시도, 성공/실패·처리량·오류 유형 |

댓글 수집이 없으므로 `replies` 테이블도 아직 만들지 않습니다.
스키마 마이그레이션 도구는 초기 단계에서 제외했으며 향후 변경 시 별도 도입합니다.

## 초기 단계의 제한

- API, 재시도, 호출 한도, 페이지네이션, 토큰 갱신은 실제 어댑터 구현 단계의 과제입니다.
- 네 가지 지표가 모두 있어야 현재 점수를 계산합니다. 실사용 API에서 제공되지 않는 필드가 있으면
  모든 게시물이 제외될 수 있습니다. Phase 0 결과에 따라 동일 가용 필드 기준의 다른 점수를 설계해야 합니다.
- 동시 쓰기 실행은 지원하지 않습니다. 운영 스케줄러에서 직렬 실행하고 DB 복원·저장 충돌을 막아야 합니다.
- SQLite 결과 저장은 트랜잭션입니다. 실패 시 결과 저장을 롤백하고 실행 실패 이력을 기록합니다.
- JSON/CSV는 각각 임시 파일을 교체해 출력하지만 DB와 두 파일 전체를 하나의 원자적 작업으로 묶지는 않습니다.
  출력 중 장애가 발생하면 이전 보고서 또는 일부 새 보고서가 남을 수 있으므로 `job_runs` 성공 상태를 확인하고 재실행합니다.
- 본문 링크·질문 유무는 단순 규칙입니다. 후킹·문체·광고·제휴 판정이나 LLM 분석은 아직 없습니다.
- 예약 실행과 영속 저장 준비가 끝나기 전에는 매일 데모 데이터가 운영 결과처럼 쌓이지 않도록 수동 실행만 제공합니다.

AI 글 생성, 자동 게시, 제휴 콘텐츠 생성은 현재 범위 밖입니다.
